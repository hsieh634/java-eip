# T03.2 安全設計

## 1. 授權

| 資源 | 規則 |
|---|---|
| `GET/PUT /api/admin/geofence`、`GET /api/admin/geofence/history` | URL 規則 `/api/admin/** hasRole('ADMIN')`＋`GeofenceSettingsService.requireAdmin`（縱深防禦）＋`ActiveAccountFilter`（停用、刪除、角色變更 → 401） |
| `POST /api/attendance/clock-in`／`clock-out`、`GET /location-policy` | 已登入即可；員工身分來自 Session |
| 前端入口「定位打卡設定」 | 只對 ADMIN 顯示；這只是介面，不是安全機制 |

`admin` 與 `developer` 同為 ADMIN，權限相同；程式中沒有任何依帳號名稱的特例，也沒有定位繞過。管理員自己的打卡同樣受限制。

## 2. 威脅與對應

| 威脅 | 對應 | 限制 |
|---|---|---|
| 前端偽造 `distance`、`inside`、中心、半徑 | DTO 沒有這些欄位，多送的欄位被忽略；距離與判斷只在後端 | — |
| 改寫請求送假座標（DevTools、代理、模擬定位） | **無法防止**；只要求精度與時間合理，並保存證據供事後稽核 | 文件與畫面都不宣稱防作弊 |
| 重播舊的定位資料 | 時間窗口（−60／+10 秒）只能擋「明顯過期」的資料 | `capturedAt` 由用戶端提供，可被竄改；不能證明真實或防重播 |
| 以舊畫面（舊設定）打卡 | 後端永遠以交易內的最新快照判斷；前端按下時先取最新要求 | — |
| 兩位管理員互相覆蓋設定 | 版本比對，過期提交 409 | — |
| 設定變更不留痕跡 | 原因必填；歷程只新增（觸發器擋 UPDATE／DELETE），與設定同交易 | 有資料庫權限的人仍可 TRUNCATE（僅供測試庫清理） |
| 設定讀取失敗被當成「關閉」放行 | 讀不到設定列 → 例外 → 500，不寫入任何資料 | — |
| 員工看到他人的定位 | 沒有查詢打卡事件的 API；員工端的定位要求不含公司中心 | — |
| CSRF | 沿用 `X-XSRF-TOKEN`；`PUT` 同樣受保護 | — |

## 3. 隱私

- 只在按下「需要定位」的打卡時取得位置；不在登入、開頁時取得；不使用 `watchPosition`。
- 不受限制時不保存員工座標（即使前端送了）。
- 保存的座標只用於該次打卡的證據，沒有對外查詢 API。保存期限、告知與同意屬正式制度，本階段**未處理**（學習情境）。

## 4. 瀏覽器限制（依 MDN／W3C Geolocation API）

- Geolocation 只在安全來源（HTTPS、`localhost`／`127.0.0.1`）可用；非安全來源會以 PERMISSION_DENIED 失敗。手機用區網 `http://192.168.x.x` 開網站**不是**安全來源。
- `timeout` 不包含等待使用者授權的時間。
- `accuracy` 是 95% 信心的誤差半徑（公尺），是估計值，不是保證。
- 位置可能來自 GPS、Wi-Fi 或 IP，桌機常只有 Wi-Fi／IP 定位，精度可能不足 50 公尺。

## 5. 錯誤與登入狀態

401 才回登入頁；定位錯誤（400／422）、範圍外（403 `OUTSIDE_GEOFENCE`）、CSRF 403、5xx、網路錯誤都只顯示訊息，不登出。網路中斷時不自動重送打卡。

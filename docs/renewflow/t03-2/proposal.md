# Proposal：T03.2 公司範圍定位打卡與管理員設定

## 範圍

1. 管理員（ADMIN）設定：啟用開關、公司中心緯經度、允許半徑（10～5000 公尺）、適用操作（上班／下班／上下班）；修改需原因、確認前後差異、版本比對、只新增的歷程。
2. 員工打卡：受限制時才取得瀏覽器位置；後端驗證定位品質、計算 Haversine 距離、判斷範圍；拒絕時不寫資料。
3. 成功打卡的原始證據：獨立、只新增的事件表，保存實際採用的設定版本與內容（受限制時含定位）。
4. 一致性：打卡以 `FOR SHARE` 取得設定快照，設定修改以 `FOR UPDATE`＋版本條件更新。
5. Migration V4（只新增資料表）；V1～V3 不修改。
6. 前端：今日打卡的定位流程與錯誤狀態、管理員「定位打卡設定」頁。
7. 測試：後端整合與並行、E2E（隔離堆疊、模擬定位）、變異驗證。

## 成果定義

在隔離環境以瀏覽器模擬：管理員設定並啟用 → 員工在範圍內打卡成功、範圍外被拒絕並看到距離與半徑；定位拒絕／逾時／不可用／精度不足都能重試且不寫資料；設定與打卡同時發生時有明確且可測的先後；更正、作廢、補登不改寫原始證據。

## 明確不做

多據點、地圖選點、地址搜尋、持續追蹤、Wi-Fi／IP 限制、人臉、外勤核准、即時地圖、定位歷程頁、HTTPS 憑證或隧道、部署、T04。

## 風險

| 風險 | 緩解 |
|---|---|
| 打卡與設定修改競態，混用不同版本 | 設定列鎖＋快照；並行測試（等待方向兩種＋大量並行不混版本） |
| 證據寫入失敗留下無證據的打卡 | 同一交易；替身注入失敗驗證回滾 |
| 設定讀取失敗被當成關閉 | 讀不到 → 500；以刪除設定列、改名資料表測試 |
| 過期的定位 callback 送出錯誤操作 | 操作在按下時固定；卸載後不送；送出前確認狀態；E2E 驗證 |
| 宣稱防作弊 | 文件、畫面與學習文件都明確說明限制 |
| 手機實機無法定位（HTTP 區網） | 本階段只做 localhost 模擬；HTTPS 方案需另行同意 |

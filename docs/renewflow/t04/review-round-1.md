## 1. 問題與重現

### R1：結果不明後修改內容，重送可能遺失新內容（`frontend/src/pages/TimesheetPage.tsx`）
1. 新增 90 分鐘工時，後端已寫入，但回應遺失。
2. 畫面顯示結果不明，但欄位仍可編輯；使用者改成 120 分鐘並改內容。
3. 再送出時沿用同一個 requestId（正確），但送的是**新內容**。
4. 後端正確回 `DUPLICATE_SUBMISSION` 指向原本 90 分鐘的紀錄。
5. 前端把它當成完成並清空表單——120 分鐘與新內容都遺失，畫面卻像是已處理。
另：送出中欄位也可編輯，成功回應後換新表單會清掉「送出後才輸入」的內容。

**自動重現**：`frontend/e2e/timesheets-review.mjs` 的 R1-1、R1-2 在修正前失敗。實際紀錄：
重送內容 `[["…aeb95",90,"R1 回應遺失的那一筆"],["…aeb95",120,"R1 送出後才改的內容"]]`（同一 requestId、不同內容）。

1. 送出時後端回專案已停用 → 前端在背景重新取得專案清單。

## 2. 修正設計

### R1：requestId 與「提交內容」綁定
| 階段 | 行為 |
|---|---|
| editing | 可以編輯。送出時把欄位標準化成一份提交內容（日期、專案、分鐘數、去除空白的內容） |
| submitting | 請求進行中，整組欄位停用（`fieldset disabled`），變更處理函式也忽略輸入（第二道防線） |
| unknown（只限新增） | 網路錯誤或 5xx：保留那份提交內容（`pending`）與 requestId，表單**持續鎖定**；主要按鈕變成「重新送出原內容」，只送 `pending` |

- 回 `DUPLICATE_SUBMISSION`：代表**原提交**已存在。由於表單一直鎖在原內容，沒有任何新編輯被丟掉；提示「若要更改內容，請在清單按『修改』」。
- 明確拒絕（400、404、409 上限、專案停用）：後端沒有建立任何東西 → 回到 editing，可以修正後再送（沿用同一個 requestId，因為那個識別碼底下沒有任何紀錄）。
- 「放棄追蹤，開始新的一筆」：結果不明時先顯示警告「原提交可能已經建立…請先在清單確認，避免重複填報」，再按「確定放棄並清空」才換新表單（新的 requestId）。
- 不做：每次重試換 requestId、自動新增另一筆、取消後端去重、把重送變成隱含更新。
- 修改模式：送出中同樣鎖定；結果不明時不鎖定（再送出若原請求已生效，會得到 409 版本衝突並引導重新載入，不會誤報成功）。

**保護範圍**：只在**同一個已掛載的表單**內有效。重新整理頁面、關閉分頁或換瀏覽器後，提交快照與 requestId 不會保留（本批不做永久草稿）；此時請先查看清單確認。切頁後晚到的回應仍依既有生命週期保護忽略。

### R2：初次載入與背景更新分開（局部修正，不改共用 `useLoad`）
- 工時頁改用頁內的 `useSelectableProjects`：自己的請求序號（只採用最後發出的那一次）與掛載有效期間。
- 初次載入失敗：沒有清單，顯示錯誤與重試（沒有表單可顯示）。
- 背景更新失敗：**保留上一份清單**，表單不卸載；另外顯示「專案清單更新失敗」與「重試更新專案清單」。原本的送出錯誤保留在表單內。
- 目前選的專案不在新清單：照實保留選擇，以停用的選項標示「已停用或無法選擇，請改選」並顯示提示，不偷偷改選；最終仍由後端判定。
- 修改既有停用專案紀錄：仍列出原本的停用專案並允許維持（既有規則）。
- 共用 `useLoad` 沒有修改，其他頁面不受影響。

## 3. 驗收（`npm run e2e:timesheets-review`，隔離堆疊）

| 編號 | 情境 | 預期 |
|---|---|---|
| R1-1 | 回應遺失 → 嘗試改成 2 小時與新內容 → 重新送出 | 表單鎖在原內容；重送同 requestId、同內容；後端只有一筆 90 分；不誤報新內容已儲存；之後以「修改」改成 120 分成功 |
| R1-2 | 送出中嘗試編輯 | 輸入不被接受；成功後以原內容建立 |
| R1-3 | 每日上限拒絕 → 修正 → 再送 | 可修正並成功 |
| R1-4 | 網路錯誤（請求沒到伺服器） | 離開 loading；重送原內容後建立一筆 |
| R1-5 | 結果不明時放棄追蹤 | 先警告「可能已經建立」，確認後清空；下一筆用新的 requestId |
| R2 | 停用後送出＋背景更新失敗 → 重試 → 舊回應晚到 → 改選啟用專案送出 | 表單與草稿、送出錯誤保留；獨立的更新錯誤與重試；重試後明確標示 B 無法選擇；舊清單不覆蓋新清單；送出成功且 requestId 一路相同 |

# T04 需求與領域分析：最小專案管理與個人工時回報

## 1. 角色與使用案例

| 角色 | 使用案例 |
|---|---|
| ADMIN（`admin`、`developer`） | 建立專案；查看專案清單（含停用）；修改名稱與說明；停用與重新啟用專案。ADMIN 的額外權限只有本階段的專案管理 |
| 所有已登入且有效的使用者（EMPLOYEE、MANAGER、ADMIN） | 查看可填報的啟用專案；填寫自己的日期、專案、工作內容、時數；查看與修改自己的工時；查看期間總工時與每日合計 |

MANAGER 不因角色名稱而取得查看他人工時的權限。

## 2. 領域名詞

| 名詞 | 說明 |
|---|---|
| 專案（Project） | 代碼（建立後不可改、唯一、大寫）、名稱、說明、是否啟用、版本 |
| 工時紀錄（Timesheet entry） | 某位員工某日在某專案的一筆工作：內容、整數分鐘、版本、新增請求識別碼 |
| 每日合計 | 某人某日所有紀錄的分鐘總和（上限 1440） |
| 新增請求識別碼（requestId） | 前端每次「邏輯上的新增」產生的 UUID；同一員工不可重複，用來避免重送建立兩筆 |
| 停用 | 專案不再接受新工時；不刪除專案、不刪除也不隱藏既有工時 |

## 3. 規則

1. 業務日期為 Asia/Taipei；可填今天或過去，不可填未來。
2. 同一天可填多個專案；同一專案也可有多筆不同工作。
3. 每筆 15～1440 分鐘，15 分鐘的倍數；資料一律為整數分鐘。
4. 每人每日合計 ≤ 1440 分鐘（資料合理性上限，不是正常工時或加班規則）。
5. 工時與出勤打卡是不同資料：不依打卡、打卡時長或定位結果限制填報。
6. 停用專案：不可新增、不可把其他紀錄改到它；既有紀錄可查詢；維持原專案時可改日期、時數、內容；可改掛到其他啟用專案。
7. 過去紀錄可修改，沒有關帳或補填期限。
8. 儲存即代表已記錄，沒有草稿或簽核狀態。

## 4. 不變條件

1. 每筆分鐘數合法（資料庫 CHECK）。
2. 每人每日合計 ≤ 1440（後端交易內以員工列鎖序列化後檢查）。
3. 同一員工的 requestId 不重複（資料庫唯一限制）。
4. 專案代碼唯一（資料庫唯一限制）。
5. 員工只能讀寫自己的工時（所有查詢以 employee_id 限定；他人紀錄一律 404）。
6. 修改需版本相符，不覆蓋較新的資料（專案與工時皆是）。
7. 停用不刪除；有工時的專案與員工無法被刪除（外鍵 RESTRICT）。

## 5. 明確不做

工時簽核、草稿／送審、查看或修改他人工時、專案成員與負責人、薪資／加班／計費／預算、匯出、通知、批次填寫、工時刪除或作廢、專案篩選、T05 請假、部署。

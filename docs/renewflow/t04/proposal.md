# Proposal：T04 最小專案管理與個人工時回報

## 範圍

1. ADMIN：建立、查看、修改（名稱、說明）、停用／重新啟用專案；版本比對。
2. 所有有效使用者：查看啟用專案；新增、查看、修改自己的工時；期間總計與每日合計。
3. 規則：台北日期、不可未來、15 分鐘單位、每日 ≤ 24 小時、停用專案的新增與修改規則、重複提交防護。
4. 資料：V5（`project`、`timesheet_entry`），V1～V4 不修改，不建立預設資料。
5. 前端：「工時回報」頁、「專案管理」頁（ADMIN），沿用既有樣式、RWD、確認視窗、非同步原則。
6. 測試：後端整合（含真正並行與可控時鐘）、遷移升級、E2E（隔離堆疊）、針對性變異驗證。

## 成果定義

管理員建立專案 → 員工填多筆工時並看到正確的每日與期間合計 → 修改 → 超過上限被拒 → 專案停用後不可新增但舊紀錄可看、可依規則修改；並行、重送、過期表單、越權都有明確結果；開發資料不受影響。

## 明確不做

見 `01-requirements-and-domain.md` 第 5 節。

## 風險

| 風險 | 緩解 |
|---|---|
| 並行寫入超過每日上限 | 員工列鎖；8 個並行請求與並行修改測試；變異驗證 |
| 重送建立兩筆 | requestId 唯一＋ON CONFLICT；並行重送測試；E2E 回應遺失情境 |
| 停用與新增競態 | 專案列鎖；兩個方向的確定性鎖測試 |
| 浮點誤差與「偷偷修正」不合法時數 | 整數分鐘；整數換算；關閉 float→int |
| 越權 | SQL 所有權條件；404；變異驗證 |
| 升級破壞既有資料 | 只新增資料表；V4→V5 逐列比對測試；開發庫套用前後比對 |

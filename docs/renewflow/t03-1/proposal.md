# Proposal：T03.1

## 範圍

1. 管理權限：沿用 EMPLOYEE／MANAGER／ADMIN，ADMIN 為最高管理權限；新增僅 dev 初始化的 `developer`（ADMIN，獨立密碼設定）。
2. 員工申請：重新打卡（RESET_TODAY）與更正／補登（CORRECT_TIME）；可撤回待審申請。
3. 管理員：審核（核准／退回）、查詢員工出勤、直接更正／作廢今日紀錄、查看歷程；皆需確認與原因。
4. 資料：新 migration V3（版本、作廢、部分唯一索引、申請表、歷程表），不修改 V1／V2。
5. 前端：員工申請與歷程、管理員「出勤管理」、狀態自動重新取得（focus／切頁／跨台北日／待審輪詢）。
6. 補強 T03：E2E 的資料庫保護提前到 migration 與初始化寫入之前。

## 成果定義

員工申請 → 管理員核准 → 員工重新打卡 的完整流程可在瀏覽器完成；原始紀錄不被刪除；並行、過時、重複操作都有明確且一致的結果；管理 API 只有 ADMIN 能用；E2E 在錯誤資料庫設定下絕不先套 migration。

## 明確不做

員工管理 CRUD、全員統計報表、工時／請假、跨日班／輪班、未來時間、WebSocket、新 UI／路由套件、修改／刪除歷程的 API、替使用者作廢／核准／修改其目前的出勤。

## 風險

| 風險 | 緩解 |
|---|---|
| 部分唯一索引使 `ON CONFLICT` 失效（衝突目標不符） | 同步修改 SQL，並有並行與重新打卡測試 |
| 核准與員工打卡並行覆蓋資料 | `version` 條件更新＋部分唯一索引；並行測試 |
| 歷程寫入失敗造成「改了沒紀錄」 | 同一交易；以替身注入失敗驗證回滾 |
| 管理權限只靠隱藏按鈕 | 後端 URL 規則＋Service 檢查＋直接呼叫測試 |
| 升級時破壞使用者既有紀錄 | 預設值升級；V2→V3 升級測試；開發庫升級後比對該筆紀錄 |

# Specification：T03.1 驗收情境

「自動」＝後端整合測試；「E2E」＝`frontend/e2e/attendance-corrections.mjs`（隔離堆疊）。

| 編號 | 情境 | 預期 | 驗證 |
|---|---|---|---|
| C-01 | 申請原因空白／過長／缺必要欄位／格式錯誤 | 400 `VALIDATION_FAILED` | 自動 |
| C-02 | 沒有今日紀錄就申請重新打卡 | 409 `NO_RECORD_TO_RESET` | 自動 |
| C-03 | 同日已有待審申請再申請（含 8 個並行） | 409 `DUPLICATE_PENDING_REQUEST`；恰一筆待審 | 自動 |
| C-04 | 申請建立後出勤不變、按鈕不開放 | 紀錄與今日狀態與申請前相同 | 自動／E2E |
| C-05 | 員工 A 看不到、撤不了員工 B 的申請 | 404；清單只有自己的 | 自動 |
| C-06 | 撤回：本人待審 → CANCELLED；已處理再撤回 | 200；409 `REQUEST_NOT_PENDING` | 自動 |
| C-07 | 核准 RESET_TODAY（今日） | 原紀錄作廢且保留原時間；今日 NOT_STARTED；只有 0 筆有效紀錄 | 自動 |
| C-08 | 重新打卡後正常上班／下班 | 只有一筆有效；作廢舊紀錄仍在；列表有兩筆（作廢＋有效） | 自動／E2E |
| C-09 | 作廢紀錄不觸發「昨日未完成」提醒、不被當成工作中 | `unfinishedBefore` 為空；今日狀態只看有效紀錄 | 自動 |
| C-10 | 補登（原本沒有紀錄）、更正既有時間、撤銷誤按的下班 | 核准後出勤符合申請；`source=MANUAL`／`corrected=true`；撤銷後今日為 WORKING | 自動／E2E |
| C-11 | 更正時間驗證：未來日期／未來時間／下班早於上班／與目前相同／缺上班時間 | 400 `INVALID_REQUEST` | 自動 |
| C-12 | 跨過台北日期後核准 RESET_TODAY | 409 `RESET_DATE_PASSED`；申請仍 PENDING | 自動 |
| C-13 | 過時：申請後員工又打卡／被他人更正 | 核准 409 `REQUEST_STALE`；出勤不被覆蓋；`stale=true`；可撤回後重新提出 | 自動 |
| C-14 | 重複核准、核准後退回、撤回後核准 | 409 `REQUEST_NOT_PENDING` | 自動 |
| C-15 | 並行核准 ×8；核准與員工打卡並行（多輪） | 恰一個成功；無兩筆有效紀錄；不覆蓋較新資料 | 自動 |
| C-16 | 退回：原因必填；退回後出勤不變 | 400（空白）；REJECTED＋原因可見 | 自動／E2E |
| C-17 | 管理員核准／退回自己的申請；直接更正自己 | 403 `SELF_REVIEW_FORBIDDEN`／`SELF_CORRECTION_FORBIDDEN` | 自動 |
| C-18 | EMPLOYEE／MANAGER／匿名呼叫管理 API | 403／403／401（每個管理端點） | 自動／E2E |
| C-19 | 角色被降級後的舊 Session 呼叫管理 API | 401（需重新登入） | 自動 |
| C-20 | 直接更正：原因必填、版本相符、權限；版本不符 | 400；成功並寫歷程；409 `RECORD_CHANGED` | 自動 |
| C-21 | 直接作廢今日／非今日 | 成功並寫歷程；409 `VOID_DATE_PASSED` | 自動 |
| C-22 | 歷程內容：操作者、前後值、原因、伺服器時間、審核結果 | 與實際操作一致；時間來自 Clock | 自動 |
| C-23 | 歷程寫入失敗 | 整個操作回滾：出勤、申請狀態都不變、沒有歷程 | 自動 |
| C-24 | 歷程不可修改／刪除 | 資料庫拒絕 UPDATE／DELETE | 自動 |
| C-25 | developer：僅設定密碼時建立、為 ADMIN、dev 以外不存在、無預設密碼、與共用密碼獨立 | 如規格 | 自動 |
| C-26 | V3 migration：乾淨庫建立；升級既有 V2 資料（員工與出勤保留，預設值正確） | 通過 | 自動 |
| C-27 | 部分唯一索引：有效紀錄唯一、作廢可多筆；待審申請唯一 | 資料庫拒絕重複 | 自動 |
| C-28 | E2E 錯誤資料庫設定：migrate／seed 皆未執行；真實啟動（臨時庫）失敗且無資料表 | 通過 | 自動 |
| E-01 | 員工申請 → 管理員核准 → 員工重新打卡（瀏覽器完整流程）；歷程與作廢紀錄可見 | 通過 | E2E |
| E-02 | 補登、撤銷下班、退回、撤回；非管理員無入口且 API 403 | 通過 | E2E |
| E-03 | 行動版（申請、核准）；視窗 focus 與跨台北日期觸發重新查詢 | 通過 | E2E |

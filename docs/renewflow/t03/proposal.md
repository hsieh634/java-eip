# Proposal：T03

## 範圍
上班／下班打卡、今日狀態、本人出勤紀錄（預設本月、可選範圍）；所有受保護 API 共用的帳號有效性檢查；產品名稱調整為 TeamPortal（企業員工入口平台）；開發維護流程：保留員工 ID 與出勤資料的情況下更新開發帳號密碼雜湊。

## 成果定義
使用者能在首頁與「出勤打卡」頁打卡並看到真實資料；並行與重複請求在資料庫層被擋下並回可理解的 409；被停用的員工任何受保護請求都被拒絕；乾淨資料庫與既有 V1 資料庫都能套用 V2。

## 明確不做
工時填報、請假、主管審核、GPS／人臉辨識、薪資、加班、管理員查看全員出勤、補登／修改／刪除、跨日班／輪班、新增路由或 UI 套件、新增任何付費服務。

## 風險
| 風險 | 緩解 |
|---|---|
| 並行請求重複建立或覆蓋下班時間 | 唯一限制＋原子 SQL；以真正多執行緒的整合測試驗證 |
| 時區日期邊界（UTC 與台北日期不同） | 日期由 `Clock` 的時間點換算；可控時鐘測試 UTC 16:00 前後 |
| 每個請求多一次帳號查詢的成本 | 單列主鍵查詢；在設計文件記錄取捨 |
| E2E 寫入汙染使用者資料 | 隔離堆疊（測試庫、專用埠、專用員工） |

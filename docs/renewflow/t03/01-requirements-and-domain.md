# T03 需求與領域分析：上下班打卡與本人出勤紀錄

產品名稱：TeamPortal（企業員工入口平台）。開發方法：RenewFlow Engineering Method v2。
狀態：已實作並由作者驗證（證據見 `docs/learning/T03-attendance.md`）；**尚未經對話助理審查**。

## 1. 事項分級

| 類別 | 內容 |
|---|---|
| 已確定（來自使用者） | 上班／下班打卡、今日狀態、本人出勤紀錄（預設本月、可選範圍）、所有受保護 API 共用的帳號有效性檢查；資料庫以唯一限制＋原子 SQL 處理並行；時間由後端伺服器決定；員工身份取自 Session |
| 學習假設（不代表任何公司制度） | 見 `02-assumptions.md` 的 A-07～A-14 |
| 不做 | 工時填報、請假、主管審核、GPS／人臉、薪資、加班、管理員查看全員出勤、補登／修改／刪除出勤、跨日班／輪班 |

## 2. 角色與資料範圍

EMPLOYEE、MANAGER、ADMIN 在本階段**都只能操作自己的出勤**。角色在 T03 不影響任何端點；資料範圍規則只有一條：「資料屬於 Session 中的登入員工」。員工 ID 不接受前端傳入（路徑、查詢、本文皆然）。

## 3. 使用案例

| 編號 | 使用案例 | 正常結果 | 異常結果 |
|---|---|---|---|
| UC-11 | 上班打卡 | 建立今日紀錄，回 200 與紀錄 | 今日已有紀錄 → 409 `ALREADY_CLOCKED_IN` |
| UC-12 | 下班打卡 | 補上今日紀錄的下班時間，回 200 | 今日沒有上班紀錄 → 409 `CLOCK_IN_REQUIRED`；已下班 → 409 `ALREADY_CLOCKED_OUT` |
| UC-13 | 查今日狀態 | 200：`NOT_STARTED`／`WORKING`／`COMPLETED`＋時間＋是否有更早未完成紀錄 | 未登入 401 |
| UC-14 | 查本人出勤紀錄 | 200，日期由新到舊；預設本月；範圍最多 31 個日曆日 | 格式錯誤／起日大於迄日／超過 31 日 → 400 |
| UC-15 | 帳號被停用或刪除後的請求 | 任何受保護請求 → 401，Session 作廢，資料不被讀寫 | — |

## 4. 領域名詞與不變條件

- **業務日期（work_date）**：以 Asia/Taipei 的日曆日表示「這是哪一天的出勤」。它是由打卡的**時間點**換算出來的，不是使用者輸入。
- **時間點（instant）**：`clock_in_at`／`clock_out_at`，儲存為 UTC 時間點（`timestamptz`），回應用 ISO 8601（例：`2026-10-01T01:05:00Z`），前端以台北時區顯示。
- **出勤紀錄**：同一員工在同一業務日期**最多一筆**。

不變條件：
1. 每位員工每個業務日期最多一筆（資料庫唯一限制保證）。
2. `clock_out_at` 為 null 或不早於 `clock_in_at`（資料庫 CHECK 保證）。
3. 下班只會填入「今日」紀錄；已填過的下班時間不會被覆蓋。
4. 出勤歷史不隨員工刪除而消失（外鍵 `ON DELETE RESTRICT`：有出勤紀錄的員工無法被刪除）。
5. 寫入一律由已驗證的 Session 身份、伺服器時間決定。

## 5. 狀態（今日）

```
NOT_STARTED --上班--> WORKING --下班--> COMPLETED
   (無今日紀錄)      (有上班、無下班)    (兩者皆有；當天不能再開第二組)
```

歷史列表中，過去日期「有上班、無下班」的紀錄標為 `INCOMPLETE`（未完成）：保留原樣，不自動補下班。

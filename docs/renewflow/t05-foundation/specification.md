# Specification：T05 前置——驗收條件與測試對照

> **T05 前置子任務**。後端測試在 `backend/src/test/java/com/renewflow/eip/organization/`；E2E 為 `frontend/e2e/organization.mjs`（隔離堆疊、本次專用帳號）。

## 1. 權限

| 驗收 | 證據 |
|---|---|
| 未登入 401；EMPLOYEE／MANAGER 對所有組織 API 403；資料沒有被改 | O-01；E2E G8 |
| Service 也檢查 ADMIN（不只靠 URL） | O-01b；變異「移除 Service 檢查」使 O-01b 失敗 |
| EMPLOYEE／MANAGER 沒有入口；直接開網址顯示「只有管理員」 | E2E G8 |
| 回應不含密碼或雜湊 | O-01、O-05；E2E G2 |

## 2. 部門

| 驗收 | 證據 |
|---|---|
| 代碼正規化、格式、唯一；名稱長度 | O-02；E2E G1 |
| 改名不需原因；狀態變更需原因；沒有變更 400；過期版本 409；404；代碼不可改 | O-03 |
| 有啟用員工不可停用（附人數）；只剩停用員工可停用、員工保留部門 | O-04；E2E G6 |
| 停用 vs 指派、停用 vs 重新啟用同時發生，不變條件成立 | CC-03、CC-04 |

## 3. 員工

| 驗收 | 證據 |
|---|---|
| 建立：正規化、可登入、可打卡與填工時；密碼原樣雜湊（不 trim）；回應與歷程沒有密碼 | O-05；E2E G2 |
| 建立的拒絕：格式、72 位元組、重複、部門停用、主管無效、不存在 | O-06 |
| 修改：原因規則、沒有變更、版本 +1、過期 409 且資料不變、歷程前後值 | O-07；E2E G3、G4 |
| ADMIN 可改自己的名稱、部門、主管；不可停用或降級自己 | O-08；E2E G6 |
| 最後一位啟用 ADMIN 受保護（含同時互相降級） | O-09、CC-02；變異「移除最後 ADMIN 檢查」使 O-09 失敗 |
| 停用、改角色後舊 Session 401；停用者不能登入；重新啟用要重新登入 | O-13；E2E G5 |
| 搜尋、狀態篩選、分頁上限、萬用字元跳脫 | O-14；E2E G9 |
| 沒有部門與主管照常打卡、填工時 | O-15；E2E G7 |

## 4. 主管

| 驗收 | 證據 |
|---|---|
| 不可是自己；必須是啟用 MANAGER／ADMIN；直接與間接循環被擋；跨部門可以；可移除 | O-10；E2E G6；變異「移除循環檢查」使 O-10 失敗 |
| 同時 A→B、B→A：每輪恰好一個成功，資料庫無循環 | CC-01（8 輪） |
| 有部屬（含停用部屬）不可停用或降成 EMPLOYEE；不自動改派 | O-11；E2E G6；變異「移除部屬檢查」使 O-11 失敗 |
| 同時「指定主管」與「停用／降級主管」：沒有無效主管 | CC-05 |
| 變異「移除組織鎖」：CC-01～CC-05 全部在第 0 輪失敗 | 變異驗證 |

## 5. 歷程與交易

| 驗收 | 證據 |
|---|---|
| 歷程只新增（資料庫拒絕 UPDATE／DELETE） | O-16 |
| 歷程寫入失敗 → 業務修改一起回滾（修改、建立員工、建立部門、停用部門） | OA-01～OA-03 |
| 歷程有操作者、時間、原因、前後值；來源區分 ADMIN／系統 | O-02、O-07；SO-02；E2E G3、G6 |

## 6. Migration

| 驗收 | 證據 |
|---|---|
| 乾淨庫 V1～V6；不建立部門；既有員工未指派；資料庫限制 | OS-01、`AttendanceSchemaTest` |
| V5 → V6：employee 舊欄位投影與其他 8 張表逐列相同 | OS-02 |
| 開發庫實際升級前後比對 | 學習文件第 8 節 |

## 7. STMAX 示範組織

| 驗收 | 證據 |
|---|---|
| 非 dev 不存在；預設關閉 | SO-01 |
| 首次套用：3 部門、6 人符合示範表；帳號本身不變；來源 SYSTEM_DEMO_SEED、沒有操作者 | SO-02 |
| 重跑完全不寫 | SO-03；開發庫第二次重啟前後比對相同 |

| 管理員調整過的人不改回 | SO-05 |

| 主管已無效 → 不設定並回報 | SO-09 |

# Proposal：T05 前置——最小組織與員工管理

> **這是 T05「請假送出與主管審核」的前置子任務**，T01～T06 編號不變。本批不包含請假。

## 為什麼

T05 的請假要送給「直屬主管」審核，但目前系統只有角色（EMPLOYEE／MANAGER／ADMIN），沒有部門，也沒有「誰是誰的主管」。這些資料只能直接改資料庫，沒有畫面、沒有規則、沒有紀錄。

## 做什麼

1. ADMIN 在「組織與員工」頁管理**部門**：建立、查詢、改名、停用、重新啟用（不刪除）。
2. ADMIN 管理**員工**：建立（含初始密碼）、查詢、修改顯示名稱、角色、啟用、部門、直屬主管（不刪除、不改密碼）。
3. 守住組織的不變條件：至少一位啟用 ADMIN、主管不循環、主管必須有效、停用部門沒有啟用員工；並行時也成立。
4. 每次變更留下只新增的歷程（含原因、前後值）。
5. dev 環境把 STMAX 示範公司的六個帳號排進三個部門並設定主管（另一個開關、預設關閉）。

## 不做什麼

請假、薪資、到離職流程、多公司／租戶、自訂角色、權限設計器、多主管、部門樹、主管查看部屬資料、邀請信、忘記／重設密碼、雲端、付費服務、重構。

## 成功標準

- Max（STMAX 的 ADMIN）在開發環境看到 3 個部門與 6 位 STMAX 員工；Leo 顯示 PROJECT 與 Iris。
- 管理員建立的測試員工能登入。
- EMPLOYEE／MANAGER 沒有入口，API 403。
- 過期表單 409；停用或改角色後舊 Session 失效；循環、無效主管、部門仍有啟用員工、最後 ADMIN 都被擋下。
- 沒有部門的員工照常打卡與填工時。
- 全部後端測試、E2E、build、lint 通過；既有資料完整保留。

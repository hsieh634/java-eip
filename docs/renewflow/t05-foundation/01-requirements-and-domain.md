# T05 前置：需求與領域分析——最小組織與員工管理

> **這是 T05「請假送出與主管審核」的前置子任務**，不更動 T01～T06 編號。本批不包含任何請假功能。

## 1. 目標

讓 ADMIN 在畫面上管理部門與員工，設定每位員工的部門與直屬主管，為 T05 的請假審核提供可靠的組織資料。

## 2. 角色與使用案例

| 角色 | 使用案例 |
|---|---|
| ADMIN | 建立、查詢、修改、停用／重新啟用部門；建立員工（含初始密碼）、查詢、修改顯示名稱／角色／啟用／部門／直屬主管；查看部門與員工的操作歷程 |
| MANAGER、EMPLOYEE | 沒有組織管理權限。被指定為主管**不會**自動取得查看或審核他人資料的權限（T05 另行設計） |
| 系統（dev 示範初始化） | 只在 dev 且明確開啟時，替 STMAX 示範帳號補上部門與主管 |

## 3. 領域名詞

| 名詞 | 說明 |
|---|---|
| 部門（Department） | 平面結構（沒有上下層）；代碼建立後不可改、唯一、大寫；可停用，不可刪除 |
| 員工（Employee） | 沿用既有 `employee` 主資料與 ID；新增部門、直屬主管、版本 |
| 直屬主管（manager） | 每位員工最多一位，可沒有；必須是啟用中的 MANAGER 或 ADMIN；不可是自己；不可形成循環 |
| 角色（Role） | 「能做哪種操作」：EMPLOYEE／MANAGER／ADMIN |
| 資料範圍 | 「能操作誰的資料」：本批不改變；主管關係目前**不授與**任何資料範圍 |
| 組織操作歷程 | 只新增：操作者（或系統來源）、對象、動作、時間、前後值、原因；不含密碼 |

## 4. 規則

**部門**：代碼去除空白轉大寫、2～32 字元、`A-Z0-9_-`、唯一；名稱 1～100；不刪除；有啟用員工時不可停用；新指派的部門必須啟用；修改／停用／啟用以 ID＋版本檢查。

**員工**：員工編號與帳號必填、唯一、建立後不可改；帳號正規化與登入一致；顯示名稱 1～100；角色沿用三種；部門與主管可空；初始密碼由 ADMIN 輸入、必填、無預設、不 trim、不截斷、≤ 72 UTF-8 位元組、只存雜湊、不回傳、不記錄；不提供密碼修改；不刪除；ID＋版本檢查。

**角色與啟用**：
- ADMIN 不可停用自己、不可把自己改成非 ADMIN。
- 任何變更後至少保留一位啟用中的 ADMIN（含兩位 ADMIN 同時互相降級）。
- 仍被任何員工指定為主管的人，不可停用、不可改成 EMPLOYEE（先重新指派或移除下屬的主管）。
- 停用或角色變更後，舊 Session 在下一個受保護請求失效（沿用 `ActiveAccountFilter`）。
- 重新啟用員工時，若其部門已停用，必須同時改到啟用部門或移除部門。

**主管**：不可自己；不可直接或間接循環（含並行互指）；必須是啟用中的 MANAGER／ADMIN；部門與主管是不同關係，允許跨部門主管；不自動替任何人改主管。

**原因與歷程**：角色、啟用、部門、主管變更必填原因；建立與一般名稱修改也記錄但不強迫原因；業務修改與歷程同一交易。

## 5. 不變條件

1. 啟用中的 ADMIN 至少一位。
2. 主管關係無循環，且沒有人是自己的主管（資料庫 CHECK 擋直接自指）。
3. 每位員工的主管若存在，必為啟用中的 MANAGER 或 ADMIN（因為「有下屬者不可停用或降成 EMPLOYEE」）。
4. 停用的部門沒有啟用中的員工。
5. 部門代碼、員工編號、帳號唯一（資料庫唯一限制）。
6. 組織歷程只新增，與業務修改同成同敗。

## 6. 明確不做

請假、薪資、到離職完整流程、多公司、多租戶、自訂角色、細粒度權限設計器、多主管、部門樹、主管查看他人出勤／工時、邀請信、忘記密碼、密碼重設、雲端部署、付費服務、全面重構。

# Specification：T05 驗收條件與證據

後端測試在 `backend/src/test/java/com/renewflow/eip/leave/`；E2E 是 `frontend/e2e/leave.mjs`，在隔離堆疊用本次專用帳號執行。

## 1. 正常流程

| 驗收 | 證據 |
|---|---|
| 送出 → 直屬主管核准 → 員工看到結果；分鐘數由後端計算；歷程有送出與核准 | L-01；E2E V1、V3、V4 |
| 退回需原因、員工看到退回原因；撤回待審 | L-02；E2E V3、V4 |
| 終態不能再轉移（核准已撤回、撤回已核准、退回已退回），被拒時資料與歷程不變 | L-02 |

## 2. 輸入

| 驗收 | 證據 |
|---|---|
| 半小時刻度、結束晚於開始、不跨午夜、原因 1～500、日期 ±365 天、假別、缺 requestId | L-03 |
| 前端送的 `minutes`、`status`、`employeeId` 被忽略 | L-03 |
| 畫面顯示時段長度，並明示未扣休息、不是計薪工時；結束早於開始由前端提示 | E2E V1、V2 |

## 3. 重疊

| 驗收 | 證據 |
|---|---|
| 相鄰可以；重疊拒絕且不改任何資料；已核准仍占用；退回／撤回釋放；不同日期、不同員工互不影響 | L-04；E2E V2 |
| 並行送出 3 筆互相重疊的申請（8 輪）：每輪恰好一筆成功、資料庫沒有重疊 | LC-01 |

## 4. 資料範圍與禁止自審

| 驗收 | 證據 |
|---|---|
| 他人申請 404；非指派主管不能讀或核准；EMPLOYEE 沒有審核清單（403）；ADMIN 不是審核人也不能核准；MANAGER 沒有管理 API 與員工管理權 | L-05；E2E V5、V6 |
| 指定自己為審核人 400；改派給申請人 400；ADMIN 不能改派自己的申請（403）；另一位 ADMIN 可以；資料庫 CHECK | L-06；E2E V6、V7 |

## 5. 審核人

| 驗收 | 證據 |
|---|---|
| 指定優先；移除後採直屬主管且只影響之後；都沒有 → `NO_VALID_APPROVER`；指定審核人無效 → 拒絕、不自動改用主管 | L-07；E2E V5、V6 |
| 指定審核人不改主管關係（Max → Iris 情境） | L-08；E2E V6；開發庫唯讀檢查 |
| 送出後改主管或改指定設定，既有申請不偷偷改派 | L-09 |
| 改派：原審核人失去權限、新審核人可處理、原因必填、版本 +1、歷程前後、已結案不能改派 | L-10；E2E V7 |
| 審核人被降級：舊 Session 401；重新登入後沒有審核權；ADMIN 改派後繼續 | L-11 |
| 取鎖後重新確認操作者：等待期間被降級或停用 → 401、沒有寫入 | L-12；組織 O-09 |
| 並行「審核人被降級」vs「審核人核准」：不會由已降級者核准 | LC-05 |

## 6. 重複提交與版本

| 驗收 | 證據 |
|---|---|
| 相同 requestId＋相同內容 → 200 原申請、一筆、一個歷程；不同內容 409 不改原申請；不同員工獨立；撤回後重送不重建；改主管後重送沿用原審核人 | L-13 |
| 並行送出同一 requestId 3 次（8 輪）：一筆、一個歷程 | LC-02 |
| 前端：回應遺失 → 鎖定原內容；重試被拒仍鎖定；重送同 requestId 得到「已建立」，只有一筆 | E2E V9 |
| 過期版本 → 409，資料與歷程不變 | L-14；E2E V8 |
| 並行核准 vs 撤回、核准 vs 改派（各 8 輪）：只有符合最新狀態與版本的成功 | LC-03、LC-04 |

## 7. 歷程、交易、Migration

| 驗收 | 證據 |
|---|---|
| 歷程只新增；CHECK 擋不合法時段、分鐘數、無決定者的結案 | L-15 |
| 歷程寫入失敗 → 送出、核准、退回、撤回、改派、設定都整筆回滾 | LA-01～LA-03 |
| 乾淨庫 V1～V7；V6 → V7 既有 11 張表逐列相同 | LS-01、LS-02 |
| 開發庫套用 V7：既有表逐列相同、新表為空 | `verification.md` 第 3 節 |

## 8. 指定設定、清單、前端

| 驗收 | 證據 |
|---|---|
| 指定設定：原因必填、版本衝突、無效審核人、相同 400、歷程、只有 ADMIN | L-16；E2E V6 |
| 清單：狀態、日期範圍、分頁上限、排序、ADMIN 依員工篩選 | L-17 |
| 載入中、錯誤＋重試、空狀態、手機寬度、沒有未處理例外 | E2E V5、V9、V10 與各段 |
| 版本或狀態衝突時不假裝成功，提示重新載入 | E2E V8 |

## 9. 變異驗證（改壞 → 對應測試失敗 → 還原）

| 改壞的保護 | 失敗的測試 |
|---|---|
| 移除重疊檢查 | L-04、LC-01 |
| 送出不取組織鎖 | LC-01、LC-02 |
| 審核人範圍改成任何人 | L-05、L-10 |
| 允許 ADMIN 改派自己的申請 | L-06 |
| 忽略版本（Service 與 SQL 兩層都移除） | L-14 |
| requestId 不比對內容 | L-13 |
| 吞掉歷程寫入失敗 | LA-02 |
| 取鎖後不重新確認操作者 | L-12、O-09 |

# Proposal：T05 請假申請與主管審核

## 為什麼

T05 前置已經有部門與直屬主管，但員工還沒有辦法請假，主管也沒有審核對象。這一批把「送出 → 審核 → 查看結果」做成可實際操作的完整流程。

## 做什麼

1. 員工送出事假／病假／特休（單日、半小時刻度），查看清單、詳情、歷程，撤回待審申請。
2. 審核人只看到指派給自己的申請，核准或退回（原因必填）。
3. ADMIN：
   - 查詢所有申請；
   - 改派待審申請（原因必填，不能改派自己的）；
   - 設定「指定請假審核人」，例如 Max 的請假由 Iris 審核，**不改**組織的主管關係。
4. 保護：
   - 重疊時段；
   - 重複提交（requestId，內容不同 409）；
   - 版本衝突；
   - 並行核准、撤回、改派；
   - 禁止自審；
   - 取鎖後重新確認操作者。
5. 只新增的歷程，與業務修改同成同敗。

## 不做什麼

額度、年資、薪資、法規計算、排班、國定假日、休息時間扣除、自動修改出勤或工時、多關簽核、代理人、通知、附件、已核准申請的取消或改單、草稿、雲端、T06。

## 成功標準

- STMAX 情境：Leo、Mia、Ryan → Iris；Iris、Zoe → Max；Max → 指定 Iris。
- 完整流程在 E2E 隔離堆疊可操作。
- 後端全部測試、全部 E2E、build、lint 通過。
- 關鍵保護的變異驗證能被測試抓到。
- 開發庫套用 V7 後既有資料逐列相同。
